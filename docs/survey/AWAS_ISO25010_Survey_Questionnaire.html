Part II. System Evaluation (ISO/IEC 25010)

#Statement54321
A. Functional Suitability — The degree to which AWAS provides functions that meet stated and implied needs.
1Completeness: The system provides all the functions needed for water billing: consumer records, meter reading, bill generation, payment recording and reports.
2Completeness: The system supports online membership application and approval.
3Correctness: The system computes water bills accurately based on meter readings and billing rates.
4Correctness: The system shows the correct balance, payment history and unpaid bills of each consumer.
5Appropriateness: The functions help users finish tasks such as recording payments and viewing bills easily.
B. Performance Efficiency — The performance of AWAS relative to the resources it uses.
1Time behavior: Pages load within a few seconds.
2Time behavior: Searching consumers, generating bills and producing reports are fast.
3Time behavior: New meter readings and notifications appear without long delays.
4Resource utilization: The system runs smoothly without slowing down the device.
5Capacity: The system handles many consumers, bills and simultaneous users without problems.
C. Compatibility — The degree to which AWAS works with other systems and environments.
1Co-existence: The system runs alongside other applications on the same device without conflict.
2Interoperability: The system works properly with online payment (GCash) and email notifications.
3Interoperability: Bills and receipts can be printed or downloaded correctly.
4Interoperability: Reports exported from the system can be opened in other programs.
D. Usability — The degree to which AWAS can be used effectively, efficiently and with satisfaction.
1Appropriateness recognizability: I can easily tell whether the system fits my needs.
2Learnability: The system is easy to learn even without training.
3Operability: Menus, buttons and forms are easy to use and control.
4User error protection: The system prevents mistakes and shows clear error messages.
5User interface aesthetics: The layout, colors and fonts are pleasing and consistent.
6Accessibility: The system is easy to use on both computers and smartphones.
E. Reliability — The degree to which AWAS performs its functions without failure over time.
1Maturity: The system works without errors or crashes during normal use.
2Availability: The system is accessible whenever I need it.
3Fault tolerance: The system keeps working even when wrong inputs or connection problems occur.
4Recoverability: Data such as readings, bills and payments are not lost after an error or interruption.
F. Security — The degree to which AWAS protects information and data.
1Confidentiality: Only authorized users can view consumer records, bills and payments.
2Integrity: Bills, readings and payment records cannot be changed without authorization.
3Non-repudiation: Each payment and transaction has a receipt or record as proof.
4Accountability: Actions are linked to the user account that performed them.
5Authenticity: The system verifies users through login, email verification and role-based access (Admin, Meter Reader, Consumer).
G. Maintainability — The degree to which AWAS can be modified and improved efficiently. (For IT experts / developers only.)
1Modularity: The system is divided into modules, so changing one does not affect the others.
2Reusability: Components of the system can be reused in other features or systems.
3Analysability: Errors and their causes are easy to find.
4Modifiability: Billing rates, puroks, settings and FAQs can be updated without changing the code.
5Testability: The functions of the system can be easily tested.
H. Portability — The degree to which AWAS can be transferred to other devices or environments.
1Adaptability: The system works on different browsers (Chrome, Edge, Firefox) and screen sizes.
2Installability: The system can be installed or deployed easily on a new server or computer.
3Replaceability: The system can replace the current manual or old billing process.
